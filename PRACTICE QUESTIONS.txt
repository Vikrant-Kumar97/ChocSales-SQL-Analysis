  ----What are Window Functions in SQL?

A Window Function performs a calculation across a set of related rows without combining those rows into a single row.

In simple words:

Window Functions allow you to calculate something about other rows while still keeping the original rows in your result.

They are commonly used for:

Ranking
Finding top N records
Running totals
Moving averages
Comparing a row with previous/next rows
Calculating percentages
Finding highest/lowest values within groups
1. Why do we need Window Functions?

Let's use your ChocSales table.

Suppose you want to find the total sales for each Sales_Person.

With GROUP BY:

SELECT Sales_Person,
       SUM(Amount) AS Total_Sales
FROM ChocSales
GROUP BY Sales_Person;

You might get:

Sales_Person	Total_Sales
Amit	25,000
John	35,000
Sarah	28,000

The individual sales records are gone from the result.

But suppose you want:

Sales_Person	Amount	Total_Sales
Amit	5,000	25,000
Amit	8,000	25,000
Amit	12,000	25,000
John	10,000	35,000
John	25,000	35,000

You want the individual rows + the salesperson's total.

That's where a Window Function is useful.

SELECT Sales_Person,
       Amount,
       SUM(Amount) OVER(PARTITION BY Sales_Person) AS Total_Sales
FROM ChocSales;
2. GROUP BY vs Window Function

This is one of the most important interview concepts.

GROUP BY
SELECT Sales_Person,
       SUM(Amount) AS Total_Sales
FROM ChocSales
GROUP BY Sales_Person;

Combines rows.

Window Function
SELECT Sales_Person,
       Amount,
       SUM(Amount) OVER(PARTITION BY Sales_Person) AS Total_Sales
FROM ChocSales;

Keeps the rows.

Easy way to remember:

GROUP BY → Collapse rows

Window Function → Keep rows + perform calculation

3. Basic Syntax

Most Window Functions follow this structure:

FUNCTION() OVER(
    PARTITION BY column
    ORDER BY column
)

For example:

ROW_NUMBER() OVER(
    PARTITION BY Country
    ORDER BY Amount DESC
)

There are three important parts:

FUNCTION()

What calculation do you want?

Examples:

ROW_NUMBER()
SUM()
AVG()
COUNT()
RANK()
DENSE_RANK()
PARTITION BY

Defines the group/window.

PARTITION BY Country

means:

Calculate separately for each country.

ORDER BY

Defines the order inside that window.

ORDER BY Amount DESC

means:

Highest amount first.

4. Example: ROW_NUMBER()

Suppose you want to rank every sale:

SELECT Sales_Person,
       Amount,
       ROW_NUMBER() OVER(
           ORDER BY Amount DESC
       ) AS Row_Num
FROM ChocSales;

Result:

Sales_Person	Amount	Row_Num
John	15,000	1
Amit	12,000	2
Sarah	10,000	3
John	8,000	4

This is useful when you need Top 1, Top 2, Top 10, etc.

5. Example: Ranking within each Country
SELECT Country,
       Sales_Person,
       Amount,
       ROW_NUMBER() OVER(
           PARTITION BY Country
           ORDER BY Amount DESC
       ) AS Row_Num
FROM ChocSales;

Now numbering starts again for every country.

Country	Sales_Person	Amount	Row_Num
India	Amit	15,000	1
India	John	10,000	2
India	Sarah	8,000	3
USA	John	20,000	1
USA	Amit	12,000	2
USA	Sarah	9,000	3
6. Example: Running Total

Window Functions are also useful for running totals.

SELECT [Date],
       Amount,
       SUM(Amount) OVER(
           ORDER BY [Date]
       ) AS Running_Total
FROM ChocSales;

Example:

Date	Amount	Running_Total
Jan 1	5,000	5,000
Jan 2	7,000	12,000
Jan 3	4,000	16,000
Jan 4	8,000	24,000

Each row can see the previous rows and calculate the cumulative total.

7. Example: LAG()

Window Functions can also compare the current row with a previous row.

SELECT [Date],
       Amount,
       LAG(Amount) OVER(
           ORDER BY [Date]
       ) AS Previous_Amount
FROM ChocSales;

Result:

Date	Amount	Previous_Amount
Jan 1	5,000	NULL
Jan 2	7,000	5,000
Jan 3	4,000	7,000
Jan 4	8,000	4,000

This is useful for things like:

Previous month's sales
Previous day's revenue
Change from previous transaction
8. Common Window Functions You Should Learn

For your SQL/Data Analyst preparation, I recommend learning them in this order:

Level 1 — Ranking
ROW_NUMBER()
RANK()
DENSE_RANK()
Level 2 — Aggregation
SUM() OVER()
AVG() OVER()
COUNT() OVER()
MIN() OVER()
MAX() OVER()
Level 3 — Previous/Next Row
LAG()
LEAD()
Level 4 — Advanced
FIRST_VALUE()
LAST_VALUE()
NTILE()
⭐ Why do we use Window Functions?

The main reason is:

They allow us to perform calculations across related rows without losing the detail of individual rows.

For example, you can answer questions like:

"What is the highest sale for each salesperson?"

"What is the running total of sales?"

"What is the previous sale amount?"

"What percentage of total sales does each transaction represent?"

"What are the top 3 sales for each country?"

These are much easier with Window Functions.

🧠 The most important concept

Remember this:

GROUP BY
    ↓
Groups rows together
    ↓
Fewer rows in output

Whereas:

WINDOW FUNCTION
    ↓
Looks across related rows
    ↓
Keeps individual rows
    ↓
Adds calculation/ranking to each row

And the three keywords you should master are:

FUNCTION() OVER(
    PARTITION BY ...
    ORDER BY ...
)

FUNCTION() → What calculation?

PARTITION BY → For which group?

ORDER BY → In what order?

Once you understand these three, ROW_NUMBER(), RANK(), DENSE_RANK(), LAG(), LEAD(), and running totals become much easier.

💡 Interview Tip

Remember the difference between WHERE and HAVING:

WHERE	HAVING
Filters rows before grouping	Filters groups after grouping
Cannot use aggregate functions like SUM(), COUNT(), AVG()	Can use aggregate functions
Used before GROUP BY	Used after GROUP BY

A common interview question is: "Can we use WHERE and HAVING together?"
Answer: Yes. WHERE filters individual rows first, then GROUP BY forms groups, and finally HAVING filters those groups.

----Absolutely. Here is the side-by-side comparison of ROW_NUMBER(), RANK(), and DENSE_RANK() using your ChocSales data.

ROW_NUMBER() vs RANK() vs DENSE_RANK()

Suppose we have:

Sales_Person	Amount
John	10,000
Amit	8,000
Sarah	8,000
David	5,000
Rahul	3,000

We use:

ROW_NUMBER() OVER(ORDER BY Amount DESC)
RANK() OVER(ORDER BY Amount DESC)
DENSE_RANK() OVER(ORDER BY Amount DESC)
Side-by-side result
Sales_Person	Amount	ROW_NUMBER()	RANK()	DENSE_RANK()
John	10,000	1	1	1
Amit	8,000	2	2	2
Sarah	8,000	3	2	2
David	5,000	4	4	3
Rahul	3,000	5	5	4
🔥 The Main Difference
Feature	ROW_NUMBER()	RANK()	DENSE_RANK()
Same values get same number?	❌ No	✅ Yes	✅ Yes
Unique number for every row?	✅ Yes	❌ No	❌ No
Can ranks be skipped?	❌ No	✅ Yes	❌ No
Ties allowed?	❌	✅	✅
Common use	Unique row numbering	Competition ranking	Ranking without gaps
Easy Example to Remember

Imagine the scores are:

100
90
90
80
ROW_NUMBER()
100 → 1
90  → 2
90  → 3
80  → 4
RANK()
100 → 1
90  → 2
90  → 2
80  → 4
DENSE_RANK()
100 → 1
90  → 2
90  → 2
80  → 3
🧠 Best Trick to Remember

Think about the 90, 90 tie:

ROW_NUMBER()

"I don't care about ties."

1, 2, 3, 4
RANK()

"Ties share the rank, so I skip the next rank."

1, 2, 2, 4
DENSE_RANK()

"Ties share the rank, but I don't skip."

1, 2, 2, 3
⭐ Interview Answer

If an interviewer asks:

What is the difference between ROW_NUMBER, RANK and DENSE_RANK?

You can answer:

ROW_NUMBER() gives every row a unique sequential number. RANK() gives the same rank to tied values but skips the next rank. DENSE_RANK() also gives the same rank to tied values, but does not skip ranks.

That is the key difference you need to remember.
